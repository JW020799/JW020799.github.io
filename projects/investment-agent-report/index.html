프로젝트 개요

이 프로젝트는 실제 투자 판단용 서비스가 아니라, AI 서비스 백엔드에서 자주 쓰이는 데이터 수집, 임베딩, 벡터 검색, 에이전트 역할 분리, 리포트 생성 흐름을 한 번에 연결해보기 위한 개인 데모입니다. 외부 데이터를 가져오고, 검색 가능한 지식으로 저장한 뒤, 역할별 로직을 조합해 결과를 만드는 데 집중했습니다.

서비스 흐름

1. 사용자 입력

사용자가 기업 티커와 분석 요청을 입력하면 전체 리포트 생성 흐름이 시작됩니다.

2. 데이터 수집

Google News RSS와 yfinance를 통해 뉴스와 재무 데이터를 수집합니다.

3. RAG 검색

뉴스 문서를 임베딩해 ChromaDB에 저장하고, 질문과 관련 높은 문서를 검색합니다.

4. Agent 리포트

뉴스, 재무, 리스크, 최종 리포트 역할을 나누어 투자 참고 리포트를 생성합니다.

구현 기능

  • Google News RSS 기반 기업 뉴스 수집
  • yfinance 기반 재무 데이터 수집 및 fallback 처리
  • Sentence-Transformers 기반 문서 임베딩
  • ChromaDB 기반 벡터 저장 및 코사인 유사도 검색
  • Planner, RAG, News, Finance, Risk, Report 역할 분리
  • FastAPI API와 Streamlit 화면 구성
  • 외부 데이터 호출 실패 시에도 흐름이 중단되지 않도록 예외 처리
  • GitHub 포트폴리오용 README, 구조, 실행 방법 정리

문제 해결 과정

외부 API 제한 대응

PROBLEM

yfinance 호출 중 429 Too Many Requests가 발생하면 전체 리포트 생성이 중단될 수 있었습니다.

SOLUTION

재무 데이터 수집 실패 시 기본값과 에러 메시지를 반환하도록 fallback을 적용해 서비스 흐름을 유지했습니다.

뉴스 문서 검색

PROBLEM

수집한 뉴스 전체를 그대로 리포트에 사용하면 관련성이 낮은 기사까지 섞일 수 있었습니다.

SOLUTION

뉴스를 임베딩해 ChromaDB에 저장하고, 코사인 유사도 기반 Top-K 검색으로 관련 문서만 사용했습니다.

역할별 처리 분리

PROBLEM

하나의 함수에서 뉴스, 재무, 리스크, 최종 리포트를 모두 처리하면 구조가 쉽게 복잡해졌습니다.

SOLUTION

Planner, RAG, News, Finance, Risk, Report 역할을 분리해 Agent Workflow 형태로 정리했습니다.

검증 가능한 데모 구성

PROBLEM

AI 프로젝트는 결과만 보여주면 내부 흐름을 확인하기 어렵습니다.

SOLUTION

FastAPI와 Streamlit을 함께 사용해 요청, 검색 결과, 리포트 생성 흐름을 빠르게 확인할 수 있게 구성했습니다.
