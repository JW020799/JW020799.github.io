문제에서 서비스 흐름까지

집수리는 사용자가 적정 가격, 추가 비용 가능성, 작업 범위, 시공자 신뢰도를 사전에 판단하기 어렵다는 문제가 있습니다. TUKTAK은 사용자가 사진과 설명을 입력하면 AI가 먼저 기준 견적과 리스크 정보를 제공하고, 이후 시공자 제안 비교까지 이어지는 흐름으로 정보 비대칭을 줄이는 것을 목표로 설계했습니다.

서비스 · 배포 아키텍처

React 프론트엔드, FastAPI 메인 백엔드, AI Service, MySQL/RDS, ChromaDB, S3 이미지 저장소를 분리한 구조로 설계했습니다. 사용자는 프론트엔드에서 견적을 요청하고, 메인 백엔드는 서비스 데이터를 관리하며, AI Service는 견적 생성과 RAG 리스크 리포트 생성을 담당합니다.

User Flow

사진과 설명 입력 → AI 견적 확인 → 리스크 리포트 확인 → 시공자 제안 비교

Frontend

React 기반으로 견적 요청, 리포트 조회, 매칭, 리뷰 흐름을 제공합니다.

Main Backend

FastAPI 기반으로 사용자, 견적, 리포트, 매칭, 리뷰 데이터를 관리합니다.

AI Service

LangGraph, ChromaDB, 임베딩 모델, LLM 연동 흐름을 별도 서버로 분리했습니다.

Data Layer

MySQL/RDS에 서비스 데이터를 저장하고, ChromaDB에 RAG 문서 벡터를 저장합니다.

Deploy

S3, CloudFront, ECR, ECS, RDS 기반의 AWS 배포 구조를 설계했습니다.

설계와 구현 범위

저는 AI 백엔드와 리스크 리포트 흐름을 중심으로 구현 기준을 정리했습니다. 특히 RAG 문서 검색, 이미지 유사사례 검색 threshold, AI Service 연동 구조, Risk Report API 구조처럼 AI 결과가 실제 서비스 응답으로 이어지는 부분을 담당했습니다.

  • Risk Report 도메인 모델 및 API 구조 구현
  • Main Backend와 AI Service 연동 구조 정리
  • ChromaDB 기반 RAG 검색 흐름 설계 및 구현
  • RAG 검색 결과의 UNKNOWN / FAILED 예외 기준 정리
  • 이미지 유사사례 검색 threshold 설계
  • Nomic Embed Vision 이미지 임베딩 검색 구조 검토
  • Ko-SRoBERTa 기반 RAG 문서 임베딩 모델 선정 검토
  • 발표자료 및 시연영상 제작

AI 핵심 흐름

01

입력 유효성 검사

사진 품질과 텍스트 유효성을 먼저 검사해 견적에 사용할 수 있는 입력인지 판단합니다.

02

NLP 구조화

설명 텍스트에서 카테고리, 수리 대상, 문제 유형, 예상 작업, 부족 정보를 구조화합니다.

03

유사 사례 검색

이미지/텍스트 임베딩과 threshold 기준으로 기존 수리 사례를 검색합니다.

04

견적 생성

유사사례와 기준표를 우선 사용하고, 부족한 경우 LLM 기반 생성 흐름으로 보완합니다.

05

RAG 리스크 리포트

소비자원, 표준계약서, 시방서 등 근거 문서를 검색해 추가 비용과 주의사항을 정리합니다.

문제 해결 과정

프로젝트 관리 방식 전환

PROBLEM

Notion 기반 기록만으로는 일정, 산출물, 담당자, 작업 상태를 명확하게 추적하기 어려웠습니다.

SOLUTION

Jira를 도입해 Epic, Sprint, Task 단위로 작업을 쪼개고 우선순위와 진행 상태를 관리했습니다.

AI 모델 배포 과부하

PROBLEM

Fine-tuning 모델을 직접 운영하는 경우 초기 인프라 비용과 운영 부담이 커질 수 있었습니다.

SOLUTION

Hugging Face repo를 활용해 모델 관리 방식을 정리하고, 초기 서비스는 GPT-5 mini와 외부 API 중심으로 검증하도록 설계했습니다.

RAG 검색 품질 저하

PROBLEM

LangChain 기본 임베딩 모델 사용 시 한국어 리스크 문서 검색 결과가 부정확했습니다.

SOLUTION

임베딩 모델 성능평가를 직접 수행하고 Ko-SRoBERTa로 교체해 한국어 문서 검색 품질을 개선했습니다.

AI 견적 신뢰성

PROBLEM

LLM 단독 추론은 임의 가격 생성과 JSON 형식 오류가 발생할 수 있었습니다.

SOLUTION

표준 단가표, 유사 사례 검색, 필수 Key 검증, 가격 범위 후처리를 함께 적용해 견적 응답 안정성을 높였습니다.

설계와 협업 산출물

RAG 구현 테스트

리스크 유형별 문서 검색, Top-K, threshold, FAILED 기준을 검증했습니다.

이미지 Threshold 설계

이미지 유사사례 검색에서 오답 통과를 줄이기 위한 모델/유사도 방식 비교를 진행했습니다.

서비스 시연 자료

사용자와 시공자의 실제 서비스 흐름을 보여주는 발표자료와 시연영상을 제작했습니다.

프로젝트 결과

TUKTAK은 AI 견적, RAG 리스크 리포트, 역경매 매칭, 시연 가능한 웹 서비스 흐름까지 연결했습니다. 이 과정에서 AI 모델 자체보다 더 중요한 것은 모델 결과를 서비스 기준으로 검증하고, 근거 부족과 오답 통과를 어떻게 제어할지라는 점을 확인했습니다.
