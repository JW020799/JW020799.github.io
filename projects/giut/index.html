프로젝트 개요

GIUT Festival Guide는 전국 축제 정보를 기반으로 사용자가 지역, 날짜, 키워드에 맞는 행사를 탐색하고, GPT 추천 코스를 저장한 뒤 마이페이지에서 다시 확인할 수 있도록 만든 웹 서비스입니다. 단순 행사 목록 조회를 넘어 사용자 액션, 추천 코스 저장, 문의와 관리자 답변까지 연결하는 흐름을 목표로 했습니다.

핵심 기능

TourAPI 축제 조회

한국관광공사 TourAPI를 활용해 전국 축제 목록과 행사 상세 정보를 조회합니다.

검색 / 필터링

지역, 날짜, 키워드 조건으로 사용자가 원하는 축제를 빠르게 찾을 수 있게 구성했습니다.

GPT 추천 코스

지역, 날짜, 키워드 입력값을 바탕으로 조건에 맞는 추천 코스 3가지를 생성합니다.

저장 / 문의 / 알림

좋아요, 북마크, 리뷰, 코스 저장, 문의 답변, 알림 조회까지 사용자 기능으로 연결했습니다.

사용자 흐름

01

메인 탐색

사용자는 메인 화면에서 축제를 검색하고 필터를 적용합니다.

02

행사 상세

행사 상세 정보와 지도 위치를 확인하고 좋아요, 북마크, 리뷰를 남깁니다.

03

AI 추천

지역, 날짜, 키워드를 입력해 GPT 기반 추천 코스를 생성합니다.

04

저장 / 재확인

추천 코스를 저장하고 마이페이지에서 북마크와 저장 코스를 다시 확인합니다.

담당 구현 범위

6명 팀에서 역할을 기능 단위로 나눴고, 저는 이벤트 조회 / 필터 API를 맡았습니다. 인증 · AI 추천 · 지도 · 좋아요 · 북마크 · 리뷰와 각 화면은 다른 팀원이 담당했습니다.

  • Event · EventDetail 모델과 Pydantic 스키마 설계
  • 한국관광공사 API 응답 구조를 서비스 기준 테이블로 재설계 (컬럼 19개 → 10개)
  • 지역 · 날짜 · 키워드 복합 조건 필터링과 선택적 필터 조합
  • GET /api/events: 행사 목록 조회 (필터 적용)
  • GET /api/events/{content_id}: 행사 상세 조회
  • GET /api/events/top · /regions/{region}/top: 전국 TOP 10 · 지역 TOP 3
  • GET /api/events/autocomplete: 헤더 자동완성 검색

시스템 아키텍처

Frontend

React / Vite / Tailwind CSS

사용자 화면에서 행사 탐색, 상세 조회, 추천 요청, 마이페이지 흐름을 제공합니다.

Backend

FastAPI / SQLAlchemy / Pydantic

인증, 사용자 기능, 행사 데이터, 추천 요청 API를 처리합니다.

Database

MySQL

사용자, refresh token, 행사 데이터, 북마크, 저장 코스, 문의와 알림 데이터를 저장합니다.

External API

OpenAI / TourAPI / Naver Map

GPT 추천, 한국관광공사 행사 데이터, 지도 위치 표시 기능을 외부 API로 연결했습니다.

문제 해결 과정

공공데이터 응답 구조를 그대로 옮긴 Event 모델

PROBLEM

컬럼이 19개로 늘고 모든 컬럼에 event_ 접두어가 붙어 Pydantic 스키마와 이름이 어긋났고, 화면에서 쓰지 않는 필드까지 관리해야 했습니다. 한국관광공사 API 응답 필드(contentid, mapx / mapy, lclsSystm3 등)를 서비스 요구와 무관하게 그대로 옮긴 것이 원인이었습니다.

SOLUTION

화면에 필요한 필드(제목 · 지역 · 기간 · 장소 · 이미지 · 설명 · 좋아요 수) 중심으로 재설계하고 접두어를 제거했습니다. EventDetail도 같은 기준으로 정리해 컬럼을 19개에서 10개로 줄이고 모델 · 스키마 필드명을 맞췄습니다.

화면마다 다른 조회 조건

PROBLEM

메인은 전국 TOP 10과 지역 TOP 3, 행사 목록은 지역 · 날짜 · 키워드 필터, 헤더는 자동완성이 필요해 한 API로는 요구를 맞추기 어려웠습니다.

SOLUTION

조회 목적별로 목록 · 상세 · TOP 10 · 지역 TOP 3 · 자동완성 API 5개로 나누고, 목록 API는 조건을 선택적으로 조합할 수 있게 구성해 화면 담당자가 필요한 응답만 받도록 했습니다.

프로젝트 결과

Event Data Model

외부 API 구조가 아니라 서비스 요구에서 모델을 시작해 컬럼을 19개에서 10개로 줄였습니다.

Event API 5개

행사 목록 · 상세 · 전국 TOP 10 · 지역 TOP 3 · 자동완성 응답을 화면 담당자에게 제공했습니다.
