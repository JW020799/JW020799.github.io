프로젝트 개요

여행이나 지역 행사를 찾을 때 사용자는 날짜, 지역, 관심사에 따라 여러 정보를 직접 비교해야 합니다. GIUT는 이 과정을 줄이기 위해 공공 행사 데이터를 한곳에 모으고, 조건에 맞는 행사 탐색과 AI 추천 코스를 제공하도록 기획했습니다.

서비스 흐름

1. 행사 데이터 수집

한국관광공사 API에서 행사 정보를 가져와 서비스 데이터로 활용합니다.

2. 검색 / 필터링

지역, 날짜, 진행 상태, 키워드 조건으로 행사 목록을 조회합니다.

3. AI 추천 요청

사용자 조건을 바탕으로 OpenAI API를 호출해 추천 코스를 생성합니다.

4. 저장 / 관리

관심 행사, 북마크, 리뷰, 추천 코스를 사용자 기능과 연결합니다.

담당 구현 범위

  • FastAPI 기반 회원가입/로그인 API 구현
  • 행사 검색 및 필터링 API 구현
  • 사용자 프로필 조회 및 수정 흐름 구현
  • 프론트엔드 화면 일부 구현 및 API 연동 흐름 확인
  • 공공데이터 API를 서비스 데이터로 활용하는 흐름 학습
  • OpenAI API 기반 추천 기능 연동 구조 이해
  • Docker Compose 기반 통합 실행 환경 경험
  • AWS EC2 서버 배포 및 컨테이너 실행 상태 확인

문제 해결 과정

API 역할 분리

PROBLEM

행사 조회, 검색, 사용자 기능이 한 흐름에 섞이면 API 책임이 불명확해질 수 있었습니다.

SOLUTION

기능 단위로 라우터와 요청 흐름을 분리하고, 프론트엔드가 필요한 응답 형태를 기준으로 API를 정리했습니다.

외부 API 연동

PROBLEM

공공데이터, 지도, AI 추천처럼 서로 다른 외부 API를 하나의 서비스 흐름에 연결해야 했습니다.

SOLUTION

API별 입력과 출력 데이터를 분리해 이해하고, 사용자 요청에서 추천 결과까지 이어지는 흐름을 문서화했습니다.

통합 실행 환경

PROBLEM

프론트엔드, 백엔드, DB를 각자 실행하면 팀원이 같은 환경을 맞추기 어려웠습니다.

SOLUTION

Docker Compose로 컨테이너 실행 구조를 맞추고, EC2 환경에서 서비스 실행 흐름을 확인했습니다.

서비스 데이터 연결

PROBLEM

행사 데이터, 사용자 활동, 추천 코스가 따로 관리되면 서비스 경험이 끊길 수 있었습니다.

SOLUTION

검색, 저장, 리뷰, 추천 코스 조회가 이어지도록 사용자 중심의 데이터 흐름을 정리했습니다.
